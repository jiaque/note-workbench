# 中英文界面支持

## 设置与语言来源

`noteWorkbench.language` 使用窗口级设置，支持 `auto`、`zh-CN`、`en`，默认 `auto`。扩展激活时读取配置及 `vscode.env.language`，统一确定本窗口语言。中文地区代码（包括 zh-TW、zh-HK）暂统一显示简体中文，其余语言显示英文。修改配置后重新加载 VS Code 窗口生效；不会为切换语言销毁正在编辑的文档。

自动模式优先使用 VS Code 界面语言，避免本机与远程扩展宿主操作系统语言不一致。共享解析函数接受系统语言作为缺失时的后备值；扩展实际使用 VS Code 提供的语言，不额外探测操作系统或提供独立的“跟随系统”选项。

## 实现范围

- `src/shared/i18n.ts` 集中管理中英文 UI 文案和带占位符的提示。中文原文作为类型化键，英文翻译必须保留占位符。
- 扩展宿主、渲染器、表格错误、PDF 导出使用同一语言。笔记、连接图与导出页面通过 HTML `lang` 接收语言，前端在首次创建界面前初始化，异步 PDF 模块也使用同一语言。
- 界面包括菜单、表格、插入对话框、浮层状态、连接图设置、空态、PDF 翻页、默认辅助标签和提示。
- 只翻译程序生成的 UI；保留作者正文、HTML、CSS、SVG 标题、路径、文件名、属性键值与图谱节点名称。新建表格的默认列名和新建空链接文字使用当前界面语言。
- `package.nls.json` 提供英文基准，`package.nls.zh-cn.json` / `package.nls.zh.json` 提供中文。设置说明、命令名称、静态侧栏名称由 VS Code 决定语言，无法用运行时配置单独切换。
- 依赖或操作系统原始错误可能沿用其自身语言；插件上下文提示已翻译。

## 验证

类型检查、61 项单元测试和隔离 VS Code 扩展宿主回归通过。新增测试覆盖手动配置优先级、中文地区代码、英文回退、占位符完整性、作者内容保持、表格默认文案、PDF 页面语言和清单翻译键完整性。

浏览器分别运行中文和英文预览：菜单、动效子菜单、插入表格对话框与英文图谱控件已核对；英文菜单中作者中文内容保持不变。独立预览服务可设置 `NOTE_WORKBENCH_PREVIEW_LANGUAGE=en` 或 `zh-CN`，前后端采用同一固定语言。
