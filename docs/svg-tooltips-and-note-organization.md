# SVG 提示与笔记组织

本轮只增加 SVG 区域提示、重命名更新引用、标签面板。其他先前讨论的 P1 增强继续暂缓。

## SVG 区域提示

### 结构化卡片与分类区间（新增）

统计图推荐用 `data-nw-tip-title` 和 `data-nw-tip-rows` 声明卡片：加粗标题、系列色点、名称和右对齐数值。旧 `data-nw-tip` 继续显示纯文本，不自动猜测字段。

```html
<rect x="200" y="30" width="200" height="170" fill="transparent"
      data-nw-tip-title="2025-09"
      data-nw-tip-rows='[{"label":"老客户","value":"240.2万","color":"#20b6b0"},{"label":"新客户","value":"53.8万","color":"#3987ff"}]'/>
```

`rows` 是 JSON 数组，`label` 与 `value` 必须为字符串，`color` 可省略，提供时只接受 `#RGB` 或 `#RRGGBB`。最多 16 行，标题和每个字段最多 200 字符，合成文本最多 2000 字符。标签和值通过 textContent 创建，颜色经过严格白名单；不开放 HTML、CSS 表达式或脚本。声明错误时仅在存在旧文本的情况下回退到旧提示。

折线图、竖向柱状/堆积图默认用每个横轴分类的**整高透明矩形**；横向条形/堆积条默认用每个纵轴分类的**整宽透明矩形**。相邻分类以中心点中线为界，首尾到绘图区边缘，不包括标题、轴标签和图例，感应区连续衔接。矩形在图形之后声明，卡片列出该分类各系列的作者提供值，保持图例顺序，不自动计算合计。饼图、桑基图、漏斗图等仍可用实际路径声明同样的卡片。

完整可运行样例见 [SVG tooltips.md](../example/SVG%20tooltips.md) 的 Axis bands 部分。

### 兼容的纯文本提示

在图形上声明 `data-nw-tip="提示文字"`，鼠标经过时由插件显示纯文本卡片，移出区域、滚动或按 Escape 后隐藏。实时预览、阅读、块预览使用相同实现；PDF 不导出提示浮层。

```html
<svg viewBox="0 0 200 100" width="400" height="200">
  <circle cx="80" cy="40" r="8" fill="#1685ef"
          data-nw-tip="2025-09&#10;新客户：53.8万"/>
</svg>
```

- 支持 `circle`、`ellipse`、`rect`、`path`、`polygon`、`polyline`、`line`。扇区、漏斗、多边形或桑基连接带可以直接用 `path` 声明，不需要声明图表类型。
- `&#10;` 表示换行。数值、百分比、名称均由作者提供；不识别任意 SVG 的统计含义、不计算总计、不执行提示中的 HTML。
- 提示区域就是图形本身。线段/折线提供约 8px 的感应宽度。要扩大圆点感应范围或展示同一月份多条线的数据，可以另加透明圆形或矩形并填写多行文字；没有自动分组或汇总。
- 多个区域重叠时，最后声明的命中区域优先。无声明的图形不弹提示，原有外观和动画保持不变。
- 支持固定的 SVG `transform`（含父级 `g`）、`viewBox` 和 `preserveAspectRatio` 缩放映射。请显式声明 `viewBox`；没有它时只能按数字宽高推导。
- 首版限定静态几何。带直接几何动画、裁剪/遮罩或内联 CSS 几何变换的区域跳过；不跟踪样式表驱动的位移、变形、隐藏，不识别 `<use>` 实例或嵌套 SVG 的区域。动态图建议另外声明固定的透明提示区域。
- Markdown 中直接编写的 SVG 和本地引用的 `.svg` 文件均支持；远程图片不会为提示而下载分析。

安全机制：原 SVG 仍经白名单过滤后作为图片显示，提示只提取受限几何和纯文本。浏览器用 Path2D 在离屏画布中做命中检测，不把 SVG 插回正文 DOM，不开放脚本、事件属性、外部资源、命令链接或 HTML 提示。最多 500 个提示区、每区 2000 字符、提示元数据合计 200KB，仍受原有 SVG 500KB / 5000 节点限制。路径长度与变换深度另有限制。

完整样例：[SVG tooltips.md](../example/SVG%20tooltips.md)。

## 重命名更新引用

默认启用设置 `noteWorkbench.notes.updateLinksOnRename`。在 VS Code 资源管理器中重命名或移动文件/文件夹时，使用 VS Code 的文件操作事件提交文本修改；支持 Wiki 链接/嵌入、Markdown 链接/定义式引用，以及 HTML 链接。保留别名、标题和块片段、链接标题以及文档其他文本。代码、公式、YAML 示例和注释不修改。

移动笔记时同时调整已识别的笔记引用和相对附件路径，防止来源目录变化导致链接失效。唯一目标才自动修改；同名歧义保留原文并提示。现有未保存内容通过 TextDocument 读取，更新走 WorkspaceEdit，不整文件覆盖或强制保存。磁盘保存遵循 VS Code 的保存机制。

范围为当前工作区的 Markdown 文件，排除 `.git`、`node_modules`、`.npm-cache`；与图谱显示过滤独立。不同工作区根目录之间不自动推断双链。操作系统、Git 或外部程序的重命名不在本功能监听范围内。与其他 Markdown 自动更新链接扩展同时启用时，应避免重复处理相同链接。

## 标签面板

Note Workbench 活动栏保留原有连接图，新增原生 VS Code **标签**视图，不重复实现文件资源管理器。

- 读取正文 `#标签` 和 frontmatter 的 `tags` 字符串/列表；支持中文和 `项目/研发` 嵌套标签，按完整标签名显示，不额外构建文件树。
- 标签不区分大小写，同一篇笔记的重复标签只计一次；代码、公式、HTML 属性、注释中的示例不算标签。
- 标签旁显示笔记数量，展开后显示对应笔记及路径，点击用 Note Workbench 打开。
- 面板顶部提供筛选；清空筛选恢复全部。正文标签链接会定位到筛选后的标签面板。
- 与现有笔记索引共用范围与增量更新；编辑、创建、删除、重命名后更新，图谱 include/exclude 配置也影响标签面板。

收藏、最近访问、复杂查询、复杂表格增强不在本轮范围。
