## 1. 产品目标

开发一个 VS Code 扩展，将现有 Obsidian Visualizer 的图谱、笔记链接能力与 Markdown Editor 的阅读、编辑体验整合起来。在同一工作台中完成“找笔记 → 阅读与修改 → 编辑表格 → 查看关联笔记”，尽量接近 Obsidian 的日常使用体验。

用户明确要求：

- 保留 Obsidian Visualizer 的能力，以及已添加的侧边栏入口。
- 像 Markdown Editor 一样查看和修改 Markdown。
- 在同一篇 Markdown 文档里正确渲染 Markdown 与 HTML 混排内容。
- 编辑表格时，鼠标经过可以出现操作入口，点击添加行、添加列、删除行、删除列。
- 新产品为独立 VS Code 扩展，首版完整支持下文定义的 Markdown 语法，包括公式、Mermaid、嵌入笔记和块引用。
- 表格保留本文件全部 P0 功能，并支持拖动调整行、列顺序。
- Git 仓库及后续上传由用户自行管理；当前完成本地开发、测试和 VSIX 试用，功能完善后再安排 Marketplace 发布。
- 本轮交付更新后的需求文档和开发文档。

核心交付判断：安装一个新扩展后，用户能够在渲染后的笔记里修改文字和表格，保存为原来的 `.md` 文件，并通过图谱继续打开、编辑其他笔记。

## 3. 已确认的整合策略

已确认交付一个独立维护的新扩展，包含统一的笔记上下文、图谱模块和增强编辑器。不要求先安装两个原扩展，也不依赖修改其安装目录。以下对比保留为方案选择依据。

| 方案 | 能解决什么 | 主要限制 | 建议 |
| --- | --- | --- | --- |
| 扩展包或快捷入口聚合 | 一起安装、集中打开已有功能 | 无法据此增加编辑器内部的 HTML 与表格交互 | 不足以满足目标 |
| 保留内置编辑器，新扩展只做图谱联动 | 可较快建立导航闭环 | 关键编辑能力取决于内置编辑器是否开放所需接口 | 可用于前期验证 |
| 独立扩展，复用图谱并提供自己的增强编辑器 | 可统一混排语义、表格操作、保存与导航 | 需要承担编辑器适配及保真测试 | 用户已确认 |

编辑架构采用源码为主的独立可视化编辑层，基线方案见开发文档。`@vscode/markdown-editor` 作为可复用候选评估，不作为项目能否启动的前提；仅在独立依赖、许可、稳定 API 和全部 P0 验证通过后替换基线内核。不能为了复用而缩减首版范围。

新编辑器建议采用 `CustomTextEditorProvider`，让 VS Code 的 `TextDocument` 承担文档状态，通过文本编辑 API 写回。官方 API 支持同一文档的多个编辑视图，并由 VS Code 提供保存、备份等基础能力；视图同步仍需扩展实现。[Custom Editor API](https://code.visualstudio.com/api/extension-guides/custom-editors)

迁移要求：保留旧扩展可回退；新旧扩展使用独立命令与视图 ID；提供采用新编辑器的入口。安装本身不应静默修改全局默认编辑器。图谱参数可从原配置读取，原扩展私有布局状态能否迁移需验证，不能预先承诺自动继承。

## 5. 工作台与笔记导航

**W-01 统一入口。** 活动栏保留类似当前图谱按钮的入口。侧边栏提供全局图谱、当前笔记局部图谱和反向链接；各视图可以折叠。全局图谱可打开到主编辑区域，避免在窄侧边栏中操作大图。文件管理首先复用 VS Code 资源管理器。

**W-02 保留定制体验。** 保留图谱配置面板四边停靠、横竖排列、参数调整与布局记忆。视图隐藏再显示或重启后恢复布局。全局与局部图谱状态分别保存。

**W-03 当前笔记上下文。** 从文件树、Wiki 链接、Markdown 链接、反向链接和图谱节点进入笔记后，编辑器和局部图谱指向同一 URI。焦点移到图谱或侧边栏时保留当前笔记；切到非笔记文件时显示清楚的空状态或“最近笔记”状态。

**W-04 导航。** 图谱双击节点打开笔记，延续现有交互；阅读模式单击正文链接跳转，编辑模式 Ctrl+单击跳转，普通单击用于编辑。反向链接列表显示来源文件与上下文摘要，点击定位到引用位置。前进/后退不丢失未保存内容。

**W-05 链接解析。** 首版支持 `[[笔记]]`、`[[路径/笔记|显示名]]`、`[[笔记#标题]]`、`[[笔记#^block-id]]`、同篇标题/块链接和 `[名称](相对路径.md#标题)`。同名文件无法唯一解析时显示候选，不静默选错。中文、空格、相对路径、Windows 路径大小写与 URL 编码进入测试范围。不存在的目标以未创建状态展示，并提供明确的创建入口。

**W-06 索引。** 编辑中的笔记以未保存文档内容更新索引；关闭且丢弃修改后恢复磁盘内容。磁盘新增、删除、改名、外部修改应更新图谱。代码块、行内代码与 HTML 注释内的示例链接不生成笔记关系。HTML 的本地 `<a href="...md">` 链接也应进入关系索引；图片不作为笔记关系。

## 6. 编辑、渲染与数据保真

### 6.1 编辑模式

**E-01 可视化编辑。** 直接在渲染后的正文中修改内容；提供常用格式操作与键盘快捷键。中文输入法组合输入期间不触发破坏光标的重渲染。任务复选框可点击切换。

**E-02 阅读与源码。** 阅读模式不显示编辑控件；源码模式始终能够编辑完整原文，可复用 VS Code 文本编辑器。模式切换保持修改状态，并尽量定位到相同内容位置。不能把“只读预览加源码编辑”视为已经满足可视化编辑需求。

**E-03 文档状态。** 支持 Ctrl+S、自动保存、Ctrl+Z、重做、未保存标记、关闭时的 VS Code 常规处理。源码视图与可视化视图共同操作同一份文档，避免各自保存独立副本。

**E-04 往返保真。** 仅打开、阅读、切换模式时，源文件不发生变更。局部编辑只修改对应内容范围，不全篇重新格式化。保留 YAML frontmatter、注释、HTML 属性、原有换行符及未支持语法的原文。若某块不能安全映射，提供该块源码编辑，不允许悄悄删除内容。

**E-05 外部变更。** 检测文档版本；旧版本的视图操作不得覆盖更新后的内容。外部编辑与当前输入发生冲突时保留双方内容，通过重新同步或冲突处理解决。文件只读时禁止写操作，仍可查看。

### 6.2 “Markdown + HTML 混排”的明确含义

首版至少包含以下三种情况：Markdown 段落之间插入 HTML 块、Markdown 文字中插入行内 HTML、文档包含原生 HTML 表格。

| 内容类型 | 渲染要求 | 首版编辑方式 |
| --- | --- | --- |
| `span`、`strong`、`em`、`br`、`sub`、`sup`、`mark` 等 | 显示合理的行内效果 | 支持范围内直接编辑；复杂属性通过局部源码修改 |
| `div`、`p`、`details`、`summary` | 按 HTML 结构展示；折叠块可展开 | 提供块级源码编辑，修改后立即重新渲染 |
| `a`、`img` | 解析相对路径，处理失效资源 | 链接、图片属性通过明确入口或源码编辑 |
| `table`、`thead`、`tbody`、`tfoot`、`tr`、`th`、`td` | 保留行列、表头和支持的样式 | 普通矩形表格直接修改和增删行列 |
| `rowspan` / `colspan` 表格 | 正确显示合并结构 | 首版保留并允许源码修改；暂禁直接增删结构 |
| 未支持的 HTML 或不完整结构 | 提供可识别的源码块/降级提示 | 原文可编辑并完整保留 |

建议默认遵循 CommonMark 的 HTML 块边界：不能笼统承诺 HTML 标签内部的 Markdown 一定递归解析；解析结果与标签类型、块边界和空行有关。`<div>**文字**</div>` 中的星号不应被擅自当成 Markdown 强调。若希望任意 HTML 容器中继续解析 Markdown，应作为明确的扩展语法另行定义。[CommonMark HTML blocks](https://spec.commonmark.org/0.31.2/#html-blocks)

渲染与保存分离：渲染层对标签、URL 和样式进行限制，但不能把过滤后的 HTML 覆盖回原始文件。文档内的 `script`、事件处理属性、`javascript:` 链接不得执行；不因打开笔记自动加载任意外部脚本或样式。允许有限的颜色、背景、对齐、宽度等样式；任意 `class` 属性可以保留，不意味着其外部 CSS 自动生效。远程图片加载提供可配置策略。

HTML 代码围栏应按代码显示，不作为 HTML 执行或渲染。这与正文中的原生 HTML 是两类内容。

### 6.3 首版完整 Markdown 支持清单

Markdown 存在多个方言。本项目以 CommonMark 0.31.2 的基础语法、GFM 的表格/删除线/任务列表/自动链接等扩展，以及下列 Obsidian 常用语法组成明确的兼容配置；差异按测试样本记录。以下各项全部为 P0，“支持”包含识别、渲染、编辑入口、保存保真和错误处理，不能仅保留源码就算完成渲染。任意第三方插件定义的语法不自动纳入范围。[GFM 规范](https://github.github.com/gfm/)

| 编号 | 语法与内容 | 首版行为 |
| --- | --- | --- |
| M-01 | 标题、段落、软/硬换行、分隔线、强调、嵌套列表、引用、缩进/围栏代码、实体和转义、参考式链接/图片 | 按规范渲染与编辑；引用定义在保存中保留 |
| M-02 | GFM 表格、删除线、任务列表、扩展自动链接 | 可视化操作与源码一致，表格符合第 7 节 |
| M-03 | 行内 `$...$` 与块级 `$$...$$` 公式 | 渲染分式、上下标、根式、矩阵、对齐等；点击局部修改 TeX 源码并即时预览；错误不影响其他正文 |
| M-04 | Mermaid 代码围栏 | 流程图、时序图、类图、状态图、ER、甘特、饼图、思维导图等；完整打包所选版本的稳定图类型；局部源码编辑并刷新图形 |
| M-05 | `![[笔记]]`、`![[笔记#标题]]`、`![[笔记#^块ID]]` | 展示整篇、章节或指定块；点击来源跳转编辑，源笔记改变后刷新；检测循环嵌入 |
| M-06 | 段落/块末尾 `^block-id`、指向块的 Wiki/Markdown 链接 | 精确定位与补全，块 ID 不出现在阅读正文；支持段落、列表、引用、表格等块的独立 ID |
| M-07 | 脚注 `[^id]` 与定义、行内脚注 `^[内容]` | 编号、往返跳转、编辑与保真 |
| M-08 | 提示块 `> [!note]`、标题、`+/-` 折叠、嵌套引用 | 渲染与折叠；未知类型用通用样式，保留类型名；兼容常用 GitHub alerts |
| M-09 | `==高亮==`、`%%注释%%`、标签 `#标签`、嵌套标签 | 对应展示或隐藏，源码可编辑；代码和公式内不误识别 |
| M-10 | YAML frontmatter 与 aliases | 可查看并编辑原始元数据；别名参与链接补全；保留未知字段 |
| M-11 | Markdown 图片和 `![[图片.png]]`、图片尺寸参数 | 本地资源显示、相对路径正确、缺失可识别；嵌入笔记内的图片按来源笔记定位 |

公式支持以选定的 MathJax TeX 功能及明确测试矩阵为准，不等同于运行完整 LaTeX 文档或任意宏包。Mermaid 以锁定版本为准，实验性图类型单独标记。完整 Obsidian 插件兼容和任意 HTML 容器内递归 Markdown 不在本次语法承诺中。

**M-12 嵌入行为。** 嵌入区域显示来源，默认只读；用户点击“编辑来源”后直接打开源笔记，不能把源笔记内容复制写回宿主。嵌套依赖按实际来源索引，不因在多处展示而伪造链接。循环或超出渲染深度时显示可跳转的占位，不无限展开；原始引用始终保留。

## 7. 表格编辑详细要求

### 7.1 悬停与焦点交互

**T-01 控件显现。** 编辑模式下，鼠标进入表格时显示轻量操作入口；移到行左侧显示行操作，移到列上方显示列操作，末行下方和末列右侧提供追加“+”。鼠标从单元格移到操作按钮时不能因离开单元格而让按钮消失。只读模式隐藏这些控件。

**T-02 插入位置。** 行操作支持“上方插入、下方插入、删除此行”；列操作支持“左侧插入、右侧插入、删除此列”。执行前高亮目标行、列或插入线，避免用户不知道按钮将影响哪里。悬停本身不修改文档。

**T-03 可访问性。** 单元格聚焦时也可打开相同操作；提供右键菜单或键盘入口。按钮显示中文提示，支持 Tab 聚焦、Enter 执行、Esc 关闭。大表格横向滚动后，控件仍对应正确的可见列。

### 7.2 增删规则

| 操作 | 预期结果 |
| --- | --- |
| 上/下插入行 | 在目标位置插入空行，保持列数与列对齐，焦点进入新行首个可编辑单元格 |
| 左/右插入列 | 给表头、数据行及必要的 Markdown 分隔行同步增列，焦点进入新列 |
| 删除行 | 删除整行；焦点进入相邻有效单元格；一次撤销恢复整次操作 |
| 删除列 | 所有行同步删列；不遗留错位单元格；一次撤销恢复整次操作 |
| 追加行/列 | 等同于末尾插入，不需要切换源码 |
| 删除最后一列 | 明确按“删除整个表格”处理，执行前确认，支持撤销 |
| 删除最后一个数据行 | Markdown 表格保留表头及分隔行，不生成格式错误的管线表格 |
| 删除 Markdown 表头 | 不提供普通“删除此行”，显示“清空表头内容”及“删除整个表格”入口 |

普通有内容的行、列删除建议采用“目标高亮 + 直接执行 + 可撤销提示”，无需每次弹窗；整表删除使用确认。结构受保护或暂不支持时，必须说明原因并提供源码入口。

### 7.3 Markdown 表格

**T-04 格式保持。** 原 Markdown 表格编辑后仍为 Markdown 表格，不自动转换成 HTML。保留左、中、右对齐信息；新增列默认左对齐。必须正确处理转义管线符、行内代码、链接、强调与 `<br>`。

**T-05 单元格输入。** Tab 移到下一格，Shift+Tab 返回上一格；在最后一格按 Tab 可新增一行。Enter 完成当前单元格编辑，Shift+Enter 插入软换行并写为 `<br>`。这些按键与中文输入法候选确认不冲突。复杂多段落或嵌套列表不能静默压成一行，可转为源码编辑。

**T-06 新建表格。** 工具栏提供插入表格入口，可选择行列数量；默认创建 Markdown 表格。对已有 HTML 表格进行修改时保持 HTML 格式。

### 7.4 HTML 表格

**T-07 普通 HTML 表格。** 无合并单元格、无嵌套表格的矩形表格必须支持与 Markdown 表格相同的增删操作。保留现有 `thead/tbody/tfoot` 分区以及未修改节点的属性；新增行位于当前分区，新增单元格按表头/数据区使用 `th/td`。表头区上方插入不伪造新的数据区。

**T-08 保真边界。** 修改单元格文字不能使整个 HTML 表格被转成 Markdown。新增节点可继承允许的展示样式，但不能复制唯一 `id`；原有未修改属性与注释不被抹除。单元格包含复杂嵌套 HTML 时，提供该单元格的源码编辑入口。

**T-09 复杂表格。** 首版识别 `rowspan`、`colspan`、嵌套表格及不规则网格。可以查看和修改源码，直接增删行列禁用并给出原因。后续支持合并表格时，必须先定义跨越插入线的单元格如何扩展、删除时如何缩减与保留内容，不能简单操作 DOM 行列下标。

本次用户要求是在原 P0 基础上增加拖动调整顺序，因此首版仍按上述普通矩形表格范围实施；合并单元格的可视化结构操作不因本次调整自动升级为 P0。

### 7.5 拖动调整行、列顺序（P0）

**T-10 拖动入口。** 行左侧、列上方显示独立拖动手柄，与增删按钮分开。拖动过程中显示被移动对象及目标插入线，靠近滚动边缘时自动滚动。松开后提交，Esc 或拖出有效区域取消；拖动中不逐帧改写文档。

**T-11 行顺序。** Markdown 表头及分隔行固定，数据行可任意重排。HTML 行在自身 `thead/tbody/tfoot` 分区内移动；首版不跨分区移动，也不将数据行变成表头。行属性及单元格内容随行移动。

**T-12 列顺序。** 移动列时，所有表头和数据行同步移动相应单元格；Markdown 对齐标记、HTML 列样式及可解析的 `colgroup` 信息跟随该列，不能只移动界面上的标题。拖动后格式仍为原 Markdown 或 HTML。

**T-13 原子性与取消。** 一次有效拖动是一次可撤销操作；原位置释放不产生修改。拖动期间文档版本发生变化时取消并刷新，不能按过期行列下标移动新内容。通过键盘或菜单“上移/下移行、左移/右移列”提供同等能力。

**T-14 边界。** 只读表格及合并单元格/嵌套表格不启用拖动。仅一行可移动数据时禁用行移动，仅一列时禁用列移动，另一方向不受影响。跨表格拖放、按单元格值自动排序以及拖动改变行高列宽不属于这次顺序调整功能。

## 8. 数据与技术约束

1. `.md` 文件是唯一正文来源；图谱索引可以重建，不作为正文数据库。
2. 采用统一的笔记 URI 和链接解析服务，图谱、编辑器、补全和反向链接共享规则。
3. 文档结构解析保留源码范围；表格操作按范围提交编辑，避免“整篇 Markdown → HTML → Markdown”造成丢失。
4. HTML 的原始内容与安全展示结果分别保存；不能从浏览器修正后的 DOM 反推出全部原文。
5. 每次行列增删或拖动重排形成一个原子文档操作；多视图更新不重复记入撤销历史。
6. 活跃笔记上下文同时支持源码编辑器和自定义编辑器，不依赖单一 TextEditor 事件。
7. 首版不依赖修改 VS Code 安装文件或原扩展打包文件；资源本地打包，核心功能离线可用。
8. 源码复用前核对具体文件与依赖的许可及来源，保留已有授权声明；本地 Obsidian Visualizer 附带 MIT 许可证。底层编辑包独立复用条件仍待验证。

| 项目 | 建议目标与样本 |

| 编辑反馈 | 100 KB、含 20 张表格的笔记，普通输入及单格修改至可见反馈 P95 ≤ 100 ms |
| 表格结构操作 | 100 行 × 20 列普通表格，增删行列至界面稳定 P95 ≤ 200 ms |

## 11. 开发阶段建议

**阶段一：验证独立编辑内核与数据保真。** 完成混排、公式、Mermaid、块/笔记嵌入及两种普通表格增删/拖动的纵向样本。通过条件是稳定 API 可用、HTML 不丢失、原子撤销成立、中文输入正常。若失败，先调整内核，不缩减 P0。

**阶段二：形成统一工作台。** 接入图谱、活动栏、局部图谱上下文、反向链接及导航，迁移本地配置面板体验。通过条件是 A01–A03、A16。

**阶段三：补齐首版全部语法与表格交互。** 完成 M-01～M-12、T-01～T-14、模式切换和同步；开发任务及依赖以开发文档为准。不能以基本 Markdown 渲染代替完整 P0。

**阶段四：本地验证与交付。** 完成 A01～A23、真实笔记副本验证及 VSIX 打包试用；源码交给用户自行纳入其 Git 仓库。Marketplace 发布等待功能完善后另行安排，A24 暂不执行，不阻塞本地首版验收。具体工期在阶段一后估算。
