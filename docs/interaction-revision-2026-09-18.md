# 编辑体验、渲染与图谱入口：需求确认稿

日期：2026-09-18。基于当前 0.3.0、用户本轮四张截图、既有需求与本机定制版 Obsidian Visualizer 核对。

**状态：用户已确认效果图和本稿方向，授权开发。保存采用推荐方案：离开块同步 TextDocument，落盘遵循 Ctrl+S / VS Code Auto Save。** 本文补充交互细节，不撤销原需求中的首版 Markdown、HTML、公式、Mermaid、嵌入、块引用、图谱及表格操作范围。下文“当前差距”保留为改动前证据；实施结果见 [开发状态](status.md)。

## 1. 我对本轮需求的理解

目标是：兼容 Obsidian 的笔记语法和链接关系，阅读排版尽量接近用户提供的紧凑网页，编辑时自然、少打扰，并与 VS Code 已有能力分工。

| 事项 | 用户已明确的方向 | 当前实现的差距 |
| --- | --- | --- |
| 表格 | 如图 1，在原单元格里直接放置光标编辑 | 如图 2、4，整格蓝框、嵌套输入框、源码文本和拖拽角标打断阅读 |
| 排版 | 接近图 3 网页；保留 Obsidian 标签识别，不照搬其过大的间隔 | 图 4 的折叠块、分隔线、标题与表格之间有明显多余留白 |
| 非表格编辑 | 接受点击后显示当前块源码；上方同时浮动显示实时渲染结果 | 当前只有源码显隐，没有所需浮层 |
| 浮层设置 | 可在设置中开关，默认开启 | 尚无该配置 |
| 左侧入口 | 打开用户定制的连接图体验 | 当前显示笔记文件列表，重复资源管理器且缺少核心图谱 |
| 产品分工 | VS Code 已经做好的通用功能直接复用 | 不应继续把文件管理做成扩展自己的平行系统 |

这里的“像 Obsidian”主要指语法和编辑能力；视觉密度以网页参照为准。编辑预览浮层是本项目的新增体验，不宣称是 Obsidian 原生交互。

## 2. 调研结果与证据

### 2.1 表格差异来自当前实现

`src/webview/editor.ts` 给活动单元格添加 `selected-cell`，并以 `textarea` 替换内容。`editor.css` 中该类明确设置了 2px outline；新版 CSS 虽覆盖了部分输入框边框，仍保留单元格选中框和 textarea 的形态。图片里的问题不能只靠换一个边框颜色解决。

Obsidian 官方表格说明支持单元格中的行内格式、Tab 换格、边缘增行列及上下文菜单。图 1 是本项目更直接的外观参照；官方说明并没有保证所有版本和主题都完全没有任何选择提示。[官方表格说明](https://obsidian.md/changelog/2023-12-26-desktop-v1.5.3/)

### 2.2 网页式紧凑不是把所有空白删掉

已只读查看用户此前提供的 HTML：它为段落、Callout、标题、分隔线和表格分别定义间距，例如段落 margin 14px、Callout margin 18px、分隔线 margin 25px，正文使用微软雅黑/sans-serif，代码才使用等宽字体。

当前插件同时存在源码空行、CodeMirror 块替换组件、块外边距、表格容器和工具预留空间。**这些层的间距叠加是待测量验证的原因判断**，不能仅凭截图给出精确像素结论。普通中文表格也应排查是否继承了编辑器等宽字体，不能用缩小字体来假装紧凑。

### 2.3 定制图谱已在本机找到

本机安装的是 `khuongduy354.obsidian-visualizer-1.1.5`，已核对其清单、README 和打包代码：

- 活动栏容器 `obsidianVisualizer`，图标为 `images/graph-sidebar.svg`。
- 侧边栏 Webview `obsidian-visualizer.globalGraphSidebar`，且代码确实注册了 Provider。
- 配置面板支持上、下、左、右停靠，以及横向/纵向排列；通过扩展状态保存布局。
- README 描述了全局/局部图、节点双击打开笔记、关联悬浮高亮、缩放和平移、节点拖动、前向/反向链接、文件名/路径过滤及参数调整。

原需求 W-01、W-02 早已要求图谱入口、保留这些定制和复用资源管理器。当前文件列表是实现未到位，不能作为图谱的替代交付。Obsidian 官方也区分全局关系图和围绕当前笔记的局部图。[官方图谱说明](https://obsidian.md/help/plugins/graph)

## 3. 表格：原位编辑，消除输入框感

**T-R01：普通单击是进入文字编辑，不是选择整格。** 光标落在点击的文字附近；不出现整格蓝框、套在格子里的矩形文本框、右下角缩放柄或强制增高的编辑区域。

**T-R02：保留行内视觉格式。** 单元格中的粗体、斜体、代码、链接等仍按格式显示。光标涉及的语法可以局部显露，但不应把整个单元格替换成一块等宽源码文本。没有“应用／取消”操作，失焦后立即恢复该格的最终渲染。

**T-R03：文字编辑与结构操作分别处理。** 文字拖选、键盘选择仍保留正常选择反馈；通过行列手柄执行结构选择或拖动时可以显示必要目标提示。这与取消普通点击时的整格蓝框不冲突。键盘焦点需可辨识，不能靠一律关闭所有焦点样式解决。

**T-R04：已有操作不缩水。** 保留行列增删、拖动重排、右键菜单、Markdown 对齐和 HTML 原属性。手柄与加号按悬停/键盘操作需求出现，不因一个单元格持续编辑就把整张表的所有控制点长期显示出来。Tab/Shift+Tab 换格，中文输入及复制粘贴不丢内容。

适用于普通 Markdown 和 HTML 表格。合并/嵌套等复杂 HTML 的兼容工作继续按原范围处理；不能把普通表格降级为源码编辑来通过本项。表格默认不触发第 5 节的块预览浮层。

## 4. 渲染：Obsidian 语法，网页式排版

**V-R01：统一展示样式。** 阅读视图、非活动编辑区和预览浮层共用解析规则与样式。浮层会因宽度不同而自然换行，但颜色、字号、行内格式及 Callout 语义一致。

**V-R02：消除重复留白。** 优先修正图 4 的“折叠 Callout → 分隔线 → 彩色标题 → 表格”链路；同时覆盖普通段落、连续标题、列表、引用、代码、公式和嵌入，不做针对单篇报告的选择器或文本匹配补丁。

**V-R03：源文件保持原样。** 调整渲染布局，而非删除 Markdown 空行、重写 HTML、压扁源码。空的锚点与内部占位节点不能产生可见大段空白；具有语义的硬换行、代码内空白和明确 HTML 间距仍需保留。

**V-R04：网页样式优先级。** 扩展默认采用紧凑、适合中文阅读的排版；文档中受支持的显式样式和用户主动配置的库内 CSS 按统一规则生效。对照 HTML 的 CSS 用于建立基线，不自动读取同名 HTML 或执行其中脚本。所有 Obsidian Callout 类型、折叠标记、Wiki 链接、嵌入、脚注、公式等识别能力保留。

**验收方式：** 使用相同视口、缩放、字体和折叠状态，测量上述四类元素边界间距，并比较整段高度。建议在实现前固定参照截图与容差，避免仅凭“看起来好一些”验收；不把不同窗口宽度下的自然换行差异算成错误。另以独立合成格式集检查通用性。

## 5. 非表格块：源码编辑 + 上方实时预览浮层

用户已经明确：允许非表格块在编辑时显示源码；浮层位于上方，实时展示修改结果；选择其他位置后结果保留，浮层消失；配置默认开启。

以下为确认后的默认行为与验收目标：

| 场景 | 建议行为 |
| --- | --- |
| 点击或键盘进入非表格块 | 原位置编辑该块；其上方出现一个只读渲染浮层，其余文档继续预览 |
| 持续输入 | 浮层按最新内容刷新，包含 Markdown、HTML、Callout、公式、Mermaid、嵌入；旧的异步结果不能覆盖新结果 |
| 块的边界 | 普通段落/标题按各自块；围栏代码、公式、HTML、Callout 按完整可解析块；嵌套列表至少包含当前项所需的结构上下文，不把整篇笔记塞进浮层 |
| 移到另一个非表格块 | 原块显示最终结果，旧浮层关闭，新块出现自己的浮层；始终只有一个 |
| 移到表格、空白、侧边栏或其他文档 | 提交当前输入到文档，关闭浮层；原块恢复渲染 |
| 点击浮层内部 | 仅操作预览，例如滚动、选择文字或展开折叠；不切换源块、不抢走正在组合的输入；浮层不提供第二个编辑入口 |
| 上方空间不够 | 优先贴住视口顶部；仍无法容纳时放到下方并限制高度，内部滚动；不遮住当前输入行 |
| 内容暂时不合法 | 局部显示解析提示，不丢源码；恢复合法后重新渲染，不用弹窗打断输入 |
| 源码为空 | 展示空结果/轻量空状态；离开后保留用户删除动作，不擅自恢复旧内容 |
| Esc | 暂时关闭浮层，不撤销输入；下次进入另一个块可以再出现 |
| 切到阅读或全文源码模式 | 不显示该浮层；再次进入实时预览按开关恢复 |
| 图谱/外链/脚注等导航 | 导航前先处理当前输入；浮层内默认不因误点打开外部页面，明确导航动作再执行 |

浮层采用覆盖层，不占据文档正常布局，不把后文往下推。浮层渲染不得重建输入区域、移动光标或终止中文输入法组合；大图、长代码、PDF 等不能无限撑高浮层。对嵌入笔记编辑的是当前嵌入语法，浮层展示解析结果，不直接修改被嵌入文件。

后续截图及范围确认：仅正在编辑的 Markdown 标题使用完整源码和统一代码字体，不应用标题字号、粗体或 HTML 内联视觉样式；最终效果由浮层展示，离开标题恢复渲染。普通段落、其他块和表格保持已有编辑行为。

配置建议为 VS Code 设置 **Note Workbench › Editor: Block Preview**，配置键 `noteWorkbench.editor.blockPreview.enabled`，布尔值，默认 `true`。支持用户级与工作区级覆盖，并对已打开的笔记立即生效。关闭时只取消浮层，原位编辑、离开后的渲染和修改同步仍保留。

### 已确认的“离开后保存”语义

离开当前块时，修改进入同一份 VS Code 文本文档，立即反映在正文并保留正常未保存标记；写入磁盘由 Ctrl+S 或 VS Code Auto Save 负责，不擅自改变用户全局自动保存设置。

不在每次失焦时强制写入磁盘。不得重新出现“应用修改”按钮；失败或冲突时要保留输入并说明状态，不能静默丢弃或假称成功。

## 6. 活动栏：连接图作为主入口

**G-R01：点击 Note Workbench 活动栏图标，侧边栏直接显示可交互的全局连接图。** 不以笔记列表、欢迎页或“点击打开图谱”的空壳按钮代替图本身。

**G-R02：保留用户定制体验。** 迁移本机图谱配置面板四边停靠、横竖布局、参数调整及布局记忆；支持在主编辑区打开大图。目标是新扩展独立具备这些能力，不要求运行时再安装旧扩展，也不直接修改旧扩展安装目录。

**G-R03：保留图谱导航与联动。** 以本机版本的节点双击打开笔记为默认；保留关联高亮、缩放平移、节点拖动、方向关系、包含/排除和图内过滤。局部图与反向链接继续作为原需求能力，跟随当前笔记；焦点移到图谱时不能丢失当前笔记上下文。图中打开笔记进入本扩展编辑器。

**G-R04：关系索引与编辑共用同一笔记上下文。** 支持原需求中的 Wiki/Markdown/受支持 HTML 链接，标题/块目标解析和嵌入关系；未保存修改、撤销、删除和外部变更按原需求更新。无需另建一份独立正文副本。

**G-R05：复用 VS Code 的通用功能。** 文件树、新建/改名/删除、通用文件搜索、标签页、设置入口、Git 和磁盘保存机制优先复用宿主。扩展负责图谱过滤、笔记关系、可视化编辑和预览等专用能力。移除当前重复的独立笔记文件列表，不删除用户文件，也不改变资源管理器。

研究发现旧扩展含有可追溯的本地备份与布局持久化代码。实现时需要比对定制与上游、整理许可和适配接口；本轮没有完成源码迁移或旧配置自动导入。采用现有布局行为不等于已保证旧扩展所有私有状态可自动迁移。
